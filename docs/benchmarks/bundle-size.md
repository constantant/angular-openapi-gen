# Bundle-size benchmark

Measured 2026-10-02. Generated by `node tools/bench/run.mjs`; the tables below are its output.

Production `main.js` of a minimal Angular app that bootstraps and calls the listed endpoints. Run `node tools/bench/run.mjs` to reproduce.

**What it measures:** how much a production Angular app grows when it uses 1 or 8 endpoints of the
76-endpoint YouTube Data API v3 spec, per generator. Each variant is a minimal app (bootstrap + the
calls, no UI) built with the esbuild application builder; "baseline" calls the same URLs with plain
`HttpClient`, and "httpResource (no generator)" calls them with bare `httpResource`, so each row can be
compared with what Angular itself costs.

Versions: angular 22.2.1, openapi-resource-gen 1.14.0, orval 8.39.0, ng-openapi-gen 1.1.0, @hey-api/openapi-ts 0.99.0.

## What the numbers say

- **Tree-shaking works as designed.** Going from 1 to 8 endpoints adds about 0.2 kB gzip in both
  flavours (the root barrel is imported, yet
  only the used tokens are kept).
- **In the default `httpResource` flavour we are not the smallest, and cannot be.** Nearly all of the
  +7 kB gzip is Angular's own `httpResource` runtime (+6.1 kB for bare `httpResource` with no generator
  at all). The generated code adds about 1 kB gzip on top. If every kilobyte matters more than signals,
  the `httpClient` flavour (`--clientType=httpClient`) costs about +1 kB gzip in total, on par with
  Orval's service classes.
- **Orval** (tags-split service classes) is the smallest for one endpoint. Its cost grows with the
  number of *tags* touched, because a service class is kept whole: 8 endpoints across several tags cost +1.2 kB, against +0.3 kB for one.
- **ng-openapi-gen 1.1** is tree-shakeable only through deep imports (`fn/<tag>/<operation>`). Its
  generated functions end with a side-effecting `fn.PATH = '…'` assignment, so importing them from the
  `functions` barrel keeps all of them (the +7 kB row; main.js more than doubles).
- **Hey API** adds a constant ~3.5 kB gzip for its client runtime, then almost nothing per endpoint.

## Caveats

- A single spec and a single scenario. Results for other specs, bigger apps or other builders may differ.
- Sizes are `main.js` only, with default esbuild production optimisation; gzip is Node's default level.
- Only the production `main.js` is measured, not runtime speed or type-check time.
- Tool versions move; the script prints the exact versions it used and installs the latest of each.
- Hey API's and Orval's Angular support is evolving; a different configuration (e.g. Orval's
  `httpResource` client) would change those rows.
